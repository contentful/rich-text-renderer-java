Critical invariants for rich-text-renderer-java. Violations here are bugs, not style issues.

MODULE DEPENDENCY DIRECTION
- core must NOT depend on html or android. The dependency graph is: html -> core, android -> core.
  Adding any import from com.contentful.rich.html or com.contentful.rich.android into core is forbidden.

RENDERER CHAIN CONTRACT
- Processor.process() returns null if no renderer matches — this is a documented API contract.
  Do not change it to throw an exception; that would be a breaking change for all consumers.
- A Renderer returning null is treated as "no match" — iteration continues to the next CheckingRenderer.
  Renderers that genuinely produce no output should return an empty string (for HTML) or empty
  CharSequence / empty View, not null.
- addRenderer appends (lowest priority). overrideRenderer prepends (highest priority).
  Never reverse this — it would silently break all consumers relying on override behavior.

EMBEDDED ENTRIES AND HYPERLINKS
- The library ships NO default renderers for CDARichHyperlinkEntry, CDARichEmbeddedInline,
  CDARichEmbeddedBlock, or their variants. These MUST be handled by consumer-provided custom renderers.
  Do not add generic/stub renderers for these types — they would silently produce incorrect output
  for consumers who have not overridden them.

ANDROID RENDERING PERFORMANCE
- The RemoveToDeepNesting simplifier exists specifically to guard against expensive native View tree
  rendering. Any change to the nesting logic must be tested against deeply nested rich text fixtures.

VERSION COORDINATION
- On every release, ALL of the following must be updated to the same version:
  - root build.gradle (project version field)
  - core/build.gradle (mavenJava publication version)
  - html/build.gradle (mavenJava publication version)
  - android/build.gradle (release publication version, inside afterEvaluate)
  - html/README.md (dependency snippet versions)
  - android/README.md (dependency snippet versions)
  Missing any of these is a release bug.

PUBLIC API SURFACE
- The following types are the public API: Processor, Renderer, RenderabilityChecker, Context,
  HtmlProcessor, HtmlContext, AndroidProcessor, AndroidContext, AndroidRenderer, Simplifier,
  Simplification, RemoveEmpties, RemoveToDeepNesting.
- Removing or renaming public methods on these types is a breaking change. Require a major version
  bump and an ADR.
